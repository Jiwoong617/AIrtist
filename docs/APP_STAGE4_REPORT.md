- **오프라인 한 경기 기능 구현 완료. 현재 PC의 짧은 반복 실행·복구 검사는 통과했으며, 번역·채점 품질과 저사양 검증은 미완료다.**
- 당시 실행: `dist/AIrtist-preview-04/AIrtist.exe`. 구버전 정리 후 현재 실행 파일은 `testbuild/AIrtist.exe`이며 폴더 전체가 필요하다. 아래 용량은 당시 측정값이고 최신 값은 [정리·재패키징 기록](WORKSPACE_CLEANUP.md)을 참고한다.
- 모델·런타임 버전은 [3단계](APP_STAGE3_REPORT.md)와 같다. 추가 다운로드·학습·새 추론 모델은 도입하지 않았다.

## 구현과 임시 규칙

`src/AIrtist.Core/MatchController.cs`에 경기 설정, 중복 없는 제시어 추첨, 작성 마감, 라운드별 결과, 누적·평균 점수와 새 경기 초기화를 추가했다. 기존 `RoundController`를 이용해 승인된 묘사를 고정하고 생성 1회·취소·AI 처리 시간 초과를 관리한다. UI는 명령과 표시만 담당한다.

기본 3라운드·작성 60초·AI 처리 180초이며 화면에서 각각 3/5/8라운드, 30/60/120초, 60/180/300초를 선택한다. 제시어는 현재 8개 목록을 경기마다 섞고 경기 안에서는 중복하지 않는다. AI 처리 시간은 제출 승인 시점부터 번역·생성·채점까지 포함한다. 작성 마감은 단조 증가 시계로 판정하며 정확히 마감 시각인 제출은 거절한다. 화면 타이머 갱신이 늦어도 제출 명령에서 마감을 다시 검사한다.

완료된 그림은 기존 평가점을 더하고, 건너뛰기·작성 시간 초과·AI 실패·취소·AI 시간 초과는 0점이다. 실패한 라운드에서 재생성하지 않고 다음 라운드로 진행한다. 정리가 끝나기 전에는 다음 라운드를 승인하지 않는다. 마지막 결과 뒤 최종 합계·전체 라운드 기준 평균·각 라운드 기록을 표시한다. 혼자 하는 경기이므로 가상의 상대나 승자를 만들지 않는다. 점수와 이 규칙은 확정된 게임 밸런스가 아니다.

이미지와 원문은 일반 실행에서 디스크에 저장하지 않는다. 다음 라운드에서 현재 이미지 참조를 해제하고, 경기 기록에는 최대 8개의 제시어·점수·상태만 보관한다. 새 경기는 이전 점수를 비운다. `MainWindow.xaml`·화면 코드와 `App.xaml.cs`에 설정/경기/최종 결과 및 `--match-smoke` 진단을 연결했다.

### 실제 반복 실행

GTX 1660 Ti 6GB, 드라이버 591.86, Ryzen 5 5600X, RAM 약 48GiB, Windows 11. 다른 앱을 종료하거나 시스템 설정을 변경하지 않았다. 512×512, 25단계, CFG 7, 단계마다 모델 세션 로딩·해제를 포함한다.

| 실행 | 전체 번역·생성·채점 시간 | 결과 |
|---|---:|---|
| 첫 생성 | 23.30초 | 완료 |
| 두 번째 생성 | 22.54초 | 완료 |
| U-Net 3/25 직전 취소 | 11.43초 | 취소로 종료 |
| 취소 후 생성 | 22.63초 | 완료 |
| 10초 제한 | 10.74초 | 시간 초과로 종료 |
| 시간 초과 후 생성 | 23.11초 | 완료 |
| 이후 생성 2회 | 22.89 / 22.13초 | 모두 완료 |

위 최종 실행은 앱과 동일하게 **라운드 사이에 GC를 강제로 호출하지 않았다.** 100ms 간격 측정의 최대 working set은 1,782,665,216바이트, 최대 private bytes는 3,679,522,816바이트였다. private bytes는 실제 상주 RAM과 같은 값이 아니다. 완료 후 private bytes는 약 184~511MB, 마지막은 약 440MB였다. 초기보다 잔류량이 늘어났으므로 이 짧은 실행만으로 장시간 누수 없음이나 최소 사양을 확정하지 않는다. 취소 시간은 요청 후 지연이 아니라 실행 시작부터 취소 완료까지다. 네이티브 정리에 따라 표시 제한보다 종료가 늦을 수 있으나 늦은 결과는 점수에 반영하지 않는다.

원자료: [최종 반복 결과](../outputs/app-stage4/stability-natural/results.json). 초기 강제 GC 진단은 `outputs/app-stage4/stability/`에 별도로 남겼으며 위 수치에 섞지 않았다. 반복 검사와 잠시 겹친 패키징·화면 검사 등 데스크톱 부하가 있었으므로 과거 대비 속도 개선 주장에 사용하지 않는다.

별도 패키지 경기 검사에서 프로세스 최대 working set 약 1.76GB, private bytes 약 3.61GB를 관측했다. 500ms 이상 간격의 `nvidia-smi` 표본에서 GPU 전체 메모리는 1,008~4,168MiB였다. 다른 앱을 포함하는 값이므로 앱 전용 VRAM 사용량이나 4GB GPU에서의 실행 성공으로 해석하지 않는다.

## 품질 결과 — 통과 아님

### 번역

23개 한국어 묘사와 영어 통과 입력 1개를 측정했다. 색·귀 길이·털색·공 2개/3개·부정 표현 일부는 보존됐지만 다음 오류가 확인됐다.

| 입력의 핵심 | 실제 출력의 문제 |
|---|---|
| 껍질을 벗겨 먹는 과일 | `Fruits that peel off.` — 먹기 전 껍질을 벗기는 관계가 불명확 |
| 비 오는 날 머리 위로 펼치는 물건 | 머리 위라는 위치가 빠짐 |
| 갈기가 있는 큰 고양잇과 동물 | `mangled meat`로 바뀌어 없는 속성이 추가됨 |
| 멍멍 짖는 작은 반려동물 | `connoitant`라는 불명확한 말과 반복된 `howling` 출력 |
| 바퀴가 두 개인 탈것 | `Two wheels in two.` — 탈것 의미가 빠짐 |
| 노란 상자 위의 빨간 공 | `in the yellow box` — 위가 안으로 바뀜 |

이는 소규모 수동 의미 점검이며 객관적인 전체 정확도로 환산하지 않았다. 제시어 별칭 차단으로 이 오류들을 모두 잡을 수 없다. 정답이나 원문에 없는 속성을 주입하는 보정은 추가하지 않았다. [24개 원문·실제 출력](../outputs/app-stage4/quality/translations.json)

### 이미지 채점

현재 TinyCLIP과 기존 `clamp((cosine-0.1)/0.3×100)` 변환을 그대로 측정했다. 생성 이미지 3장, 직접 그린 색/윤곽 사과·컵 4장, 배 형태 진단 도형, 영문/한국어 단어만 적힌 이미지 6장, 빈 이미지·잡음 등 총 16장이다. 도형 제작 코드는 검사기에 포함되어 재현 가능하며 게임의 이미지 생성 경로에는 쓰이지 않는다. `expected`는 진단 대상이며 생성 프롬프트만으로 정답 이미지를 보증하지 않는다. 특히 빨간 과일 생성물은 시각적으로 사과/토마토가 모호해 확정 정답 표본으로 세지 않았다.

| 표본 | 평가 대상 | 현재 점수 |
|---|---|---:|
| 하얀 동물 생성 이미지 | 토끼 | 89.47 |
| 손잡이 있는 파란 용기 도형 | 컵 | 88.85 |
| 같은 용기의 윤곽선 | 컵 | 87.34 |

빈 이미지의 다른 대상 점수도 높았다(토끼 78.77, 컵 75.12). 단순히 0~100 변환의 하한만 조정해서 해결됐다고 판단할 수 없다. 사과 윤곽선의 약 80점과 무관한 기하 형태의 약 87점처럼 순서가 뒤집히는 사례도 있다. 그림 화풍·유사 오답·글자를 구분하는 채점 품질은 **경쟁 게임용으로 미달**이다. UI에 평가점이 검증 중임을 표시했으며, 이 16장에 맞춰 임의의 합격 기준을 만들거나 같은 표본으로 보정 후 성능 향상을 주장하지 않았다. [대상별 전체 코사인·점수](../outputs/app-stage4/quality/scores.json)

## 용량·남은 작업

최신 패키지는 **955,602,506바이트 / 442개 파일**, 1GB 예산의 잔여는 **44,397,494바이트**다. 모델·토크나이저·.NET/WPF·ORT/DirectML·라이선스·파일 목록을 포함한다. EOS와 설치 프로그램은 없다. [용량 집계](../outputs/app-stage4/package-size.json), [패키지 통합 검사](../outputs/app-stage4/packaged-match/status.json)

다음 우선 작업은 **번역·채점 품질 개선**이다. 보정용 자료와 별도 검증 자료를 나누고 화풍·유사 오답·빈/글자 이미지 판별을 확인해야 한다. 추가 학습 없이 가능한 평가 문구·벡터·점수 변환과 예산 안의 대안을 실측하고, 번역 의미 보존도 별도로 개선한다. 동시에 별도 4GB VRAM·16GB RAM PC, 장시간 반복, 실제 IME·DPI 검증이 필요하다. 따라서 AGENTS의 4단계 전체 완료나 최소 사양 확정으로 보고하지 않는다. 이후 EOS 연결·이미지 전송·호스트 경기 동기화와 깨끗한 PC 설치 검증으로 진행한다.

Git에는 경기 소스·검사 소스·실행 스크립트와 이 보고서만 추가한다. 모델, 새 패키지, 진단 그림·점수 JSON·프로세스 기록은 기존 `.gitignore`에 따라 제외한다.
