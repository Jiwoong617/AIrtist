# 멀티플레이 진입·방 코드·자동 접속

작성: 2026-10-08. 중단된 멀티플레이 UI 작업을 이어서 구현하고 `testbuild/AIrtist.exe`에 반영했다.

같은 날 후속: 사용자 지시에 따라 멀티플레이 화면의 홍보성 문구, 카드 부제·중복 행동 문구와 부가 설명을 제거했다. 화면명·버튼명·입력 항목·필요한 상태/오류만 표시한다. `testbuild`의 변경된 앱 DLL과 manifest를 갱신하고 파일 무결성과 기존 모의 온라인 검사를 확인했다. 검사 자료는 `outputs/ui-copy-20261008/`이며 이전 DLL과 manifest는 `.cache/testbuild-before-ui-copy-20261008`에 보관했다.

## 사용 흐름

1. 메인 화면 → 멀티 플레이 → **방 생성** 또는 **방 참가**.
2. 방 생성에서는 정원·라운드·작성/생성 시간·방 파라미터 고정을 설정하고 **방 만들기**를 누른다.
3. 앱이 내부 EOS 설정으로 기기 인증하고 방을 만든다. 우측 상단의 10자리 방 코드(5-5 표시)를 클릭하면 복사한다.
4. 친구는 방 참가에서 코드를 입력한다. 소문자·하이픈·공백을 허용하고 입력 오류는 접속 전에 검사한다.
5. 참가자가 모이면 각자 **게임 준비**를 누른다. 전원 연결 합의 후 게임 대기방으로 이동하고 준비 상태를 확인한 방장이 경기를 시작한다.

멀티플레이 진입 화면은 밝은 배경, 두 개의 선택 카드, 생성 설정 카드, 코드 입력 카드와 참가자 목록으로 구성했다. 게임 대기방·경기에도 우측 상단 코드 복사 버튼을 유지한다. 그림 생성·번역·투표 규칙은 기존 규칙을 따른다.

## 구현과 제한

- `RoomCode`가 혼동 문자를 뺀 영문/숫자 10자리를 암호학적 난수로 생성한다. `airtist-` 접두사를 붙여 EOS Lobby ID로 지정한다. 별도 코드 중계 서버는 사용하지 않는다.
- 코드 참가는 EOS `LobbySearch.SetLobbyId`로 정확한 ID를 조회한다. 버킷 조건과 ID 조건은 함께 설정하지 않으며 응답의 호환성 버킷·방 ID·정원을 다시 확인하고 `LobbyDetails`로 참가한다.
- 존재하지 않거나 닫힌 방의 정확한 ID 조회가 `NotFound`를 반환하는 경우 빈 검색 결과로 처리한다. 접속 전체를 실패시키지 않고 코드를 다시 입력할 수 있게 한다.
- 기존 작업 시간 초과, 오래된 콜백 거절, 늦게 완료된 참가 정리와 명단 검증을 유지한다. 작업 스레드의 처리 확인으로 즉시 완료된 빈 검색 응답도 UI를 잠그지 않는다.
- 방 코드는 초대 편의를 위한 식별자다. 현재 방은 기존 공개 검색 가능 정책을 유지하며 비밀번호나 비공개 접근 제어를 추가한 것은 아니다.
- 명단 변경 이후의 연결 합의 재사용, 호스트 이전과 경기 중 재접속은 기존과 같이 지원하지 않는다. 모두 나간 뒤 새 방을 만든다.

## EOS 설정 내장

사용자가 **“설정 내장 승인 — 다른 PC도 파일 선택 없이 접속”**으로 ClientSecret 포함 테스트 빌드 내장을 명시적으로 승인했다. 최초 자동 승인 검토의 차단 이후 받은 승인으로 진행했다.

- `scripts/prepare-online-config.ps1`이 로컬 설정 5개를 검증하고 `.cache/online/eos-client.json`을 만든다. 값은 로그에 출력하지 않는다.
- 앱은 `AIrtist.OnlineConfig` 리소스로 이를 읽는다. 기본 실행은 외부 경로에 의존하지 않는다.
- 원본 설정과 생성 리소스, 빌드 산출물은 Git 제외다. 앱에 포함된 게임 클라이언트 값은 추출 가능하며 비밀 보관을 보장하지 않는다. 기존 사용자 인증 필수·로비 범위 정책을 사용한다.
- 개발 진단의 `--eos-config` 명시적 덮어쓰기는 유지한다. 내장 설정 없이 빌드한 경우 접속 시 설정 없는 빌드임을 알린다.

중단 직전 제한 환경의 실제 접속 검사가 실패했다. 네트워크 허용 실행에서는 인증·생성이 성공했고 닫힌 코드의 `NotFound` 처리 오류가 드러났다. 수정 뒤 실제 검사가 통과했다. 진단 코드는 격리된 호환성 범위의 임시 방을 만들고 나가며 클립보드는 테스트용 복사 수신 함수로 검사한다.

실제 서비스 검사는 **한 PC·한 참가자**다. 다른 PC의 실제 코드 참가, P2P·PNG 전송과 온라인 투표를 검증한 것으로 취급하지 않는다. 이번 변경에서 AI 생성 코드는 바꾸지 않아 실제 이미지 생성 성능 검사를 반복하지 않았다. [2PC/3PC 수동 검사](MULTIPC_TEST_GUIDE.md)를 따른다.

검사 자료는 Git 제외 `outputs/room-code-20261008/`에 있다. `live-retry`, `mock-entry`, `settings`는 개발 검사이며 `final-live`, `final-mock`, `final-startup`은 최종 `testbuild` 경로의 검사다.

## 테스트 빌드

- 실행 파일: `D:\AIrtist\testbuild\AIrtist.exe`
- 전체 폴더: **943,484,515바이트 / 444개 파일**. 1,000,000,000바이트 목표 내이며 남은 여유는 56,515,485바이트다.
- 모델·번역기·토크나이저·.NET/WPF·ORT/DirectML·EOS·단어 데이터·고지를 포함한다. EXE만 복사하지 말고 폴더 전체를 전달한다.
- 교체 전 패키지는 `.cache/testbuild-before-room-code-20261008`에 보관했다.

재현 명령(프로젝트 루트, 로컬 설정과 고정 SDK 준비 후):

```powershell
.\scripts\build-app.ps1 -PackageDirectory '.cache/testbuild-room-code-new'
.\scripts\check-app.ps1 -PackageDirectory 'testbuild' -OutputDirectory 'outputs/new-room-mock' -Mode online-smoke
.\scripts\check-app.ps1 -PackageDirectory 'testbuild' -OutputDirectory 'outputs/new-room-live' -Mode online-live-smoke
```

실제 서비스 검사는 인터넷 연결을 허용한 환경에서 실행한다. 출력 폴더는 실행마다 새 경로를 사용한다.
