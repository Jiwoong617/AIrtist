# 번역·채점 개선 결과 — 2026-09-20

> **과거 실험 기록:** 2026-09-21 기획 변경으로 AI 채점은 제품에서 제외하며 아래 채점 보정·자료 확장은 더 진행하지 않는다. 측정 결과는 보존하고 현재 작업은 [통합 기획서](../AI_Image_Game_Summary.md)의 그림그리기·멀티 투표 전환을 따른다.

채점을 TinyCLIP 40M의 혼합 INT8 저장 모델과 비교 벡터 방식으로 교체했다. 번역 후보 6개 탐색은 오역 개선이 충분하지 않아 앱에는 채택하지 않았다. 오프라인 경기 기능은 유지되며, **번역·채점의 제품 품질과 4단계 전체 완료를 의미하지 않는다.**

실행 파일은 `D:\AIrtist\testbuild\AIrtist.exe`다. 폴더 전체가 필요하다. 설치 후 필수 파일은 **963,310,223바이트 / 443개**, 1GB 예산에서 **36,689,777바이트**가 남는다. 모델·토크나이저·벡터·.NET/WPF·ORT/DirectML·라이선스를 포함하며 EOS와 설치 프로그램은 아직 없다.

## 번역: 40문장 비교, 기본값 유지

기존 개발용 24문장과 미리 고정한 추가 16문장을 각각 단일 후보/6개 후보로 번역했다. [공식 OPUS-MT 설정](https://huggingface.co/Helsinki-NLP/opus-mt-ko-en/blob/e42d1f41b66194e6d10512f8a27bebc1f4f5097e/generation_config.json)은 `num_beams=6`이지만, 이것만으로 의미 보존이 해결되지는 않았다.

| 묘사 | 단일 후보 | 6개 후보 |
|---|---|---|
| 노란 상자 위의 빨간 공 | 상자 **안**으로 번역 | 같은 오류 |
| 갈기가 있는 큰 고양잇과 동물 | `mangled meat` | `meat to grind` |
| 도로를 달리는 네 바퀴 탈것 | `Four wheels on the road.` | `Four laps on the road.` |
| 검은 줄무늬가 세 개 있는 주황색 공 | `Three-silver orange balls.` | `The orange ball with three black stripes.` |

일부 수량·수식 관계는 개선되지만 갈기·반려동물·탈것·부정의 범위 오류가 남고 악화도 있었다. 한국어 문장의 평균 실행 시간은 개발 자료 1.64→2.46초, 추가 자료 1.64→2.65초였다. 데스크톱 작업과 일부 겹친 진단 값이므로 정밀 성능 비교로 취급하지 않는다.

`LocalTranslator`는 기존 동작을 유지한다. 후보 탐색 코드는 검사 프로젝트의 `BeamSearchTranslator.cs`에만 있고 배포 앱에 포함되지 않는다. 제시어로 번역을 고치거나 대상명을 추측해 주입하지 않았다. 결과: `outputs/app-quality/translation-development.json`, `translation-holdout.json`. 문장별 수동 의미 점검이며 번역 정확도 비율은 주장하지 않는다.

## 채점: 모델·벡터·점수식을 함께 검증

기존 8M 모델에 사진/그림/일러스트 문구와 유사 오답·배경 비교 벡터를 적용하면 글자 점수는 낮아졌지만, 별도 자료의 정상 컵·우산·자동차 4장에도 0점이 나왔다. 이 후보는 채택하지 않았다.

채택한 공개 모델은 [TinyCLIP-ViT-40M-32-Text-19M-LAION400M](https://huggingface.co/wkcn/TinyCLIP-ViT-40M-32-Text-19M-LAION400M/tree/95ec8197b3f2fe7f747865c61ca556cf0768b2f7)이다. 리비전 `95ec8197b3f2fe7f747865c61ca556cf0768b2f7`, 공개 MIT 고지와 모델 카드를 패키지에 포함했다. 출처·원본 SHA-256은 `experiments/app_quality/scoring-source.json`, 배포 변환 이력은 `models/scoring/provenance.json`에 기록한다.

- 이미지 인코더와 projection을 ONNX로 변환했다. 큰 가중치 75개는 출력 채널별 INT8, 나머지 125개는 FP16 저장이며 연산은 FP32다. 학습·미세조정·직접 증류는 하지 않았다.
- FP32 ONNX 158,885,019바이트 → 배포 ONNX **40,206,075바이트**. 필수 크기는 변환 파일의 실측이다. INT8 연산 속도 향상을 뜻하지 않는다.
- 변환 점검 19장에서 원본 FP32 대비 대상 코사인 차이 최대 **0.008347**. C# 전처리를 포함한 36장 비교에서는 최대 **0.008350**이었다.
- 같은 체크포인트에서 8개 대상의 사진/그림/일러스트 문구 벡터를 평균 후 정규화했다. 가까운 오답 24종, 배경·글자 7종, 대상 단어를 글자로 적은 설명 16종을 비교 벡터로 추가했다. 제시어와 이 벡터는 채점기에만 전달한다.

임시 규칙 `tinyclip-contrast-v1`에서 대상 유사도를 `s`, 다른 대상·비교 벡터의 최대 유사도를 `b`라 하면 다음과 같다.

```text
점수 = 100 × clamp((s - 0.10) / 0.30, 0, 1)
           × clamp((s - b + 0.02) / 0.08, 0, 1)
완전히 단색인 전처리 이미지는 0점
```

단순 상대 1등에 100점을 주지 않는다. 이 값은 게임 평가점이며 정답 확률이 아니다. 벡터 차원·정규화·규칙 버전을 검사하고 실제 이미지의 인코딩으로 계산한다. 유사도와 최종 점수는 별도로 보존한다.

### 자료 분리와 결과

기존 16장 중 사과/토마토 판정이 모호한 생성물 1장을 정답 표본에서 제외하고 **15장**을 개발 자료로 사용했다. 비교용 **21장**은 별도 생성 이미지 4장과 재현 가능한 진단 그림 17장이다. 평가 전에 그림을 직접 확인하고 라벨을 정했다. 단순히 생성 프롬프트의 정답을 이미지 라벨로 사용하지 않았다. 진단 도형은 게임 생성 경로에서 사용하지 않는다.

21장은 8M/40M 후보 비교에 사용되었으므로 최종적으로 한 번만 사용한 블라인드 시험이라고 주장하지 않는다. 임계값·평가 문구는 40M의 15장 개발 자료로 고정한 뒤 21장을 평가했고 그 결과에 맞춰 다시 조정하지 않았다. 표본이 적고 일부는 같은 생성 모델의 다른 결과이므로 독립적인 일반화 정확도 증거로 취급하지 않는다.

| C# 배포 구성에서의 별도 21장 | 결과 |
|---|---:|
| 정답 그림 8장: 사과·컵·바나나·우산·자동차·토끼 | 대상 점수 77.03~90.27 |
| 무관한 그림·단어·잡음·배/병/그릇/레몬 등 13장 | 모든 게임 대상 중 최대 점수 0~8.13 |
| 같은 오답 13장의 기존 8M/기존 점수식 | 최대 대상 점수 68.43~100 |

고정된 이 21장의 회귀 기준은 정답 대상 40점 이상, 오답의 모든 대상 25점 이하이며 통과했다. 이 기준은 일반 이미지 품질의 합격선이 아니다. 개발 자료에서는 **사과 색칠 도형 12.92점, 윤곽선 22.35점**처럼 과도한 감점이 남는다. 강아지·호랑이 정답 표본, 더 많은 실제 생성물, 여러 화풍·복합 장면·철자 변형은 추가 검증이 필요하다. 현재 채점 품질 전체를 통과로 판정하지 않는다.

- `experiments/app_quality`: 고정 원본 다운로드, 평가 벡터 준비, INT8 저장 변환, 모델 manifest/고지 갱신, 진단 자료 생성 및 환경 잠금 목록.
- 규칙·경기 단위 검사 통과. CLIP 토큰 13건, Marian 토큰/실제 번역 12건, 스케줄러 25단계, 채점 전처리·참조 이미지 3건 통과.
- 새 패키지로 한국어 실제 생성 → 건너뛰기 → 영어 실제 생성 → 3라운드 최종 결과 → 새 경기 초기화 통과. 47.75초 동안 UI 타이머 405회. .NET·ORT·DirectML이 모두 패키지에서 로드됨을 확인했다.
- 위 실행은 GTX 1660 Ti 6GB/드라이버 591.86, Ryzen 5600X/RAM 약 48GiB 환경이다. 프로세스 최대 working set 약 1.78GB, private bytes 약 3.62GB. 일부 CPU 검사와 겹쳤으며 저사양 검증·전용 VRAM 측정·속도 개선 주장이 아니다.
- 패키지를 `testbuild`로 옮긴 뒤 전체 파일 해시와 최종 경로의 자체 검사를 다시 통과했다. `packaged-match` 기록의 `testbuild-quality` 경로는 이동 전 검증 위치다.

원자료: `outputs/app-quality/40m/csharp-scoring.json`, `conversion.json`, `packaged-match/`, `final-path-check/`, `package-size.json`. 이미지·모델·실행 결과·실험 환경·testbuild는 Git에서 제외하며 소스·출처·검토 보고서만 보관한다.

검증 후 이번에 만든 CPU Python 환경, 이전 패키지, 중간 ONNX, bin/obj/publish 등 **5,216,419,136바이트**를 정리했다. 작업 폴더는 정리 직후 **약 3.80GB**이며 실행에 필요한 `testbuild`는 약 963.3MB다. 고정 원본 모델·개발 캐시·검증 자료는 별도 개발용이다. 기존 8M 원본 삭제는 자동 승인 검토가 재현 자료 손실 위험으로 거절하여 보존했다. 따라서 원본을 포함한 모든 개발 자료가 앱 실행에 필요한 것은 아니다. 삭제 대상·용량은 `outputs/app-quality/cleanup-plan.json`, `cleanup-summary.json`에 남겼다.
