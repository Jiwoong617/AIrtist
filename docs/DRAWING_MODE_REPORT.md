# 그림그리기 모드 전환 — 2026-09-21

> 이 문서는 전환 1단계 당시의 측정 기록이다. 이후 채점 코드·자산·패키징 정리는 완료했으며 현재 실행 파일·용량·다음 작업은 [2026-09-22 채점 제거 보고서](SCORING_REMOVAL_REPORT.md)를 따른다.

수정 기획의 **1번 작업을 구현·검증했다.** 기존 싱글 경기 화면을 제시어·AI 채점·라운드·작성 마감 없는 그림그리기로 바꿨다. 현재 실행 파일은 `testbuild/AIrtist.exe`다. 멀티플레이와 채점 전용 자산·구형 코드의 완전 정리는 다음 작업이다.

## 구현한 동작

- `사과`, `토끼`처럼 대상 이름을 포함한 원문을 자유롭게 입력한다. 제시어를 추첨하거나 숨은 금지 별칭을 적용하지 않는다.
- 로컬 번역 확인·영어 수정·원문 복귀를 재사용한다. 원문은 2~160자, 확인 영어는 2~320자이며 특수 토큰·길이·영어 확인란의 한글 검사는 유지한다.
- 확정한 영어 문장을 그대로 생성에 사용한다. 완성 후 **다시 그리기**는 같은 문장과 새 시드로 다시 생성하며 번역을 반복하지 않는다.
- **묘사 수정**으로 영어를 고치거나 원문으로 돌아간다. 이전 완성 그림은 새 그림이 완성될 때까지 유지한다. 최근 그림 한 장만 보관하며 파일 저장 기능은 아직 없다.
- 작성·확인에는 마감이 없다. 번역과 생성 각각의 기술적 처리 제한은 180초다. 실패·취소·시간 초과 후 재시도할 수 있고 점수·생성권을 소비하지 않는다.
- Core에서 동시에 한 작업만 허용한다. 취소한 작업이 정리되기 전에는 다음 작업을 시작하지 않으며, 취소·시간 초과 뒤 도착한 결과와 오래된 초안/화면 명령을 거절한다.

## 수행한 검사

- 잠금 파일 기반 복원, 규칙 검사, Release 자체 포함 publish와 패키징 성공. 새 컴파일 경고·오류 없이 완료했다.
- 그림그리기 규칙: 대상명 직접 입력, 생성 전 번역 확인, 원문 복귀, 수정 영어의 그대로 사용, 재번역 없는 반복, 무효 입력/중복/오래된 명령 거절, 실패 복구, 취소 뒤 늦은 번역/그림 거절, 오래된 진행 메시지 무시, AI 시간 초과 후 복구, 종료 중 작업 정리 통과.
- 작성/확인은 AI 기술 제한 시간을 넘겨 대기해도 만료되지 않는 것을 검사했다. 기존 규칙·경기·번역 확인 검사도 통과했다. 구형 경기 검사는 보존 코드의 회귀 확인이며 새 그림그리기 규칙이 아니다.
- 실제 WPF EXE: 한국어 대상명 입력 → 번역 확인 → 영어 확인란의 한글 거절 → 원문 복귀 → 영어 `a white rabbit with long ears`로 수정 → 실제 생성 → 같은 묘사 재생성 → 원문을 `a red apple on a blue background`로 수정 → 실제 생성까지 **3장** 성공했다.
- 진단 전체 74.608초, UI Dispatcher 648회 응답. 실제 생성은 각각 22.501초, 22.657초, 22.729초였다. 시드 42/43/44. 첫 그림에 사용한 한국어 번역은 1.350초, 마지막 영어 입력은 번역 모델 실행을 생략했다.
- 100%·150% 및 작은 화면 렌더를 확인했다. 작은 화면에서 입력·번역 패널은 스크롤하며 주요 버튼을 사용할 수 있다. 두 입력란의 Enter는 줄바꿈이고 기본 제출 버튼이 아니다.
- .NET·ORT·DirectML이 패키지 폴더에서 로드됨을 확인했다. 등록 파일 **442개**의 크기·SHA-256 검사 후 `testbuild`로 반영했고 최종 경로 자체 검사도 통과했다.

측정 GPU는 GTX 1660 Ti 6GB / 드라이버 591.86이다. 프로세스 최대 working set **1,684,221,952바이트**, private bytes **3,597,594,624바이트**였다. GPU 기록은 다른 앱을 포함한 전체 사용량이며 앱 전용 VRAM·최소 사양·속도 개선 수치로 해석하지 않는다.

원자료: `outputs/drawing-mode/packaged-drawing/`의 `drawing-smoke.json`, `process.json`, 화면·생성 이미지와 `final-path-check/`. 패키지 검사 경로의 `testbuild-drawing`은 `testbuild`로 옮기기 전 위치다. 소스·문서를 Git에 보관하고 모델·실행 파일·이미지·로그·빌드 산출물은 제외한다.

## 용량과 다음 작업

새 `testbuild`는 **963,329,453바이트 / 443개 파일**이다. 1GB 목표 대비 잔여는 36,670,547바이트다. 기존 채점 모델·벡터와 구형 경기/채점 클래스는 아직 남아 있다. 그림그리기는 이들을 호출하지 않지만 공용 manifest 검사·패키징에는 채점 파일 요구가 남으므로 **채점 완전 제거와 용량 절감 완료로 보고하지 않는다.**

검증 후 이전 패키지와 이번 publish·bin/obj **1,506,280,333바이트**를 정리했다. 원본 모델과 검증 자료는 보존했고 정리 직후 폴더는 **3,804,489,524바이트(약 3.80GB)**다. [정리 기록](WORKSPACE_CLEANUP.md)

다음은 **2번 채점 전용 코드·모델·벡터·검사·패키징 의존성 정리**다. 멀티용 단어 목록을 벡터에서 분리하고 생성용 CLIP 텍스트 인코더·토크나이저 및 공용 이미지 기능은 유지한다. 이후 채점 파일 없는 새 패키지 실행·전체 용량을 검증한다.
