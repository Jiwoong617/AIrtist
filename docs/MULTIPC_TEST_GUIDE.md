# 여러 PC 온라인 검사 절차

갱신: 2026-10-15. **실행 준비 문서이며 여러 PC 검사 통과 기록이 아니다.**

현재 빌드는 `multiplayer-waiting-v8`이며 닉네임과 준비 상태를 한 대기방에서 처리한다. 이전 빌드와 혼용하지 않는다. 모든 화면은 한 창에서 표시하며 우측 상단 설정에서 라이트/다크 모드를 변경할 수 있다.

2026-10-14: 같은 Windows 사용자에서 앱을 여러 개 실행하는 **동일 PC 로컬 검사**도 지원한다. 앱 하나에서 방을 만들고 다른 앱에서 방 코드로 참가하면 자동 연결한다. 별도 모드 선택은 없다. 독립 프로세스 3개의 실제 생성·전송·투표는 통과했으나 아래 여러 PC의 EOS 검증을 대체하지 않는다. 로컬 참가자와 외부 PC 참가자를 같은 방에 섞지 않는다. [구현·검사](LOCAL_MULTIPLAYER_REPORT.md)

## 준비

- Windows x64 PC 두 대와 각 PC의 인터넷 연결. 다른 회선 검사는 한 PC를 휴대폰 핫스팟 등 별도 회선에 연결한다. 같은 공유기 검사는 다른 회선 검사와 따로 기록한다.
- `D:\AIrtist\testbuild` **폴더 전체**를 각 PC에 준비한다. 두 PC의 `package-manifest.json` SHA256이 같은지 확인한다. EXE만 옮기지 않는다. 개발 SDK·Python·별도 모델 다운로드는 요구하지 않는다.
- 10월 8일 이후 테스트 빌드는 승인된 EOS 게임 클라이언트 설정을 내장한다. 별도 설정 파일을 전달하거나 선택할 필요가 없다.
- 각 PC에서 먼저 그림그리기 한 장이 생성되는지 확인한다. 낮은 사양의 실제 생성 성능은 아직 검증 전이다.
- 3인 투표 검사는 세 번째 PC/참가자가 필요하다. 같은 PC·같은 Windows 사용자의 앱 두 개를 별도 기기로 취급하지 않는다.

현재 개발 PC 실행:

```powershell
& 'D:\AIrtist\testbuild\AIrtist.exe'
```

다른 PC에서도 폴더 전체를 복사한 뒤 EXE를 실행한다. 방 만들기·참가 버튼에서 기기 인증을 자동 처리한다. 플레이어용 Epic/Steam 로그인은 이 검사 방식에서 요구하지 않는다.

## 2PC: 방 참가부터 두 라운드까지

1. A는 **멀티 플레이 → 방 생성**에서 닉네임과 정원 2를 설정하고 **방 만들기**를 누른다. 오른쪽 위 방 코드를 클릭해 복사한다. B는 **멀티 플레이 → 방 참가**에서 닉네임과 받은 코드를 입력하고 참가한다.
2. 양쪽 모두 `참가자 2 / 2`인지, 입력한 닉네임·자기 이름의 `나`·A의 `방장` 표시 및 두 PC의 방 코드가 같은지 확인한다. 잘못된 코드·닫힌 방에서는 재입력이 가능해야 한다. 참가 실패·명단 불일치는 이후 단계를 통과로 기록하지 않는다.
3. 기본 대기방의 왼쪽 참가자 목록과 오른쪽 방 설정을 확인한다. B가 **준비 완료**를 누르면 A의 **게임 시작**이 활성화돼야 한다. B가 준비를 취소하면 다시 비활성화돼야 한다. A에게 별도 준비 완료 버튼이 표시되면 실패다.
4. A가 검사 설정을 2라운드·작성 300초·생성 180초로 적용한다. 이는 수동 검사 여유 시간이며 제품 기본값 변경이 아니다. 설정 변경 후 B의 준비가 해제되고 두 PC의 설정이 같아지는지 확인한다. B가 다시 준비하면 A가 **게임 시작**을 누른다. 내부 연결 준비 후 같은 창에서 경기로 이동해야 하며 별도 대기방이나 새 창이 열리면 실패다.
5. 같은 제시어/라운드가 표시되는지 확인한다. 각자 제시어와 금지 별칭을 쓰지 않은 서로 다른 묘사를 입력하고 **그림 그리기**를 한 번 누른다. 번역본 확인 없이 내부 번역·방장 승인 후 각 PC에서 한 장씩 생성해야 한다.
6. 두 PC의 갤러리에 **두 그림이 모두 나타나는지** 확인한다. 서로의 그림에서 색·형태·배치를 비교하고, 자기 그림의 투표가 비활성화됐는지 확인한다. 화면 비교는 네트워크 경로나 PNG 해시를 별도로 실측한 기록을 대신하지 않는다.
7. 서로에게 투표한다. 양쪽 모두 **1:1**이며 동일한 라운드 결과인지 확인한다. 2인 검사에서는 정상적으로 이 동점 구조가 발생한다.
8. 전원 결과 확인 후 A만 다음 라운드를 시작한다. 새 입력·새 이미지로 5~7을 반복하고 첫 라운드 기록 보존·마지막 라운드 경기 종료·두 PC의 숫자 기록 일치를 확인한다.
9. 접속을 종료한다. 새 방 생성·코드 참가가 가능한지 확인한다. 같은 경기의 진행 상태 복원은 지원하지 않는다.

## 3PC: 투표 집계

새 방에서 정원 3, 1라운드로 진행한다. 참가자 A/B/C가 각각 한 장 생성한 뒤 A→B, B→A, C→B로 투표한다. 모든 PC에서 A/B/C 그림의 득표가 **1/2/0**이어야 한다. 자기 투표·중복 확정이 허용되지 않는지 확인한다. 이 인원은 테스트 조건이며 제품 최소 인원 확정이 아니다.

## 이탈과 실패

별도 방에서 경기 시작 이후 한 참가자가 **방 나가기**를 누른다. 나머지 참가자가 계속 경기 시작/진행하지 않고 중단 상태로 바뀌는지 확인한다. 다시 모일 때는 전원이 나간 뒤 새로 접속한다. 호스트 이전·진행 중 재접속은 지원하지 않는다. 확정된 라운드 결과가 있다면 남은 화면에서 보존되는지 확인한다. 경기 시작 전 대기방의 일반 참가·이탈은 준비를 해제하고 갱신한 명단으로 계속 대기한다.

실패 시 먼저 발생한 단계·화면의 오류 문구·각 PC의 상태를 기록한다. 새 방으로 재시도하되 방화벽/보안 설정을 임의로 끄지 않는다.
