# 멀티플레이 제출 승인·이미지 전송 기반 — 2026-09-24

2026-09-25 후속 구현에서 갤러리 배포·전원 수신 확인·참가자 투표/결과 상태를 추가했다. 현재 코드는 그림 수집 직후 투표를 시작하지 않고 수신 확인을 기다린다. 이 문서는 9월 24일 당시 기록이며 [최신 동작·검사](GALLERY_SYNC_REPORT.md)를 함께 따른다.

4번 작업 중 **SDK와 독립적인 한 라운드의 호스트 처리**를 구현하고 검사했다. 최종 묘사 승인 → 실제 PNG 바이트 분할·재조립 → 기존 투표·결과 처리까지 연결했다. EOS SDK와 개발자 포털 설정이 아직 없으므로 **실제 EOS 인증·로비·P2P 접속 및 온라인 경기 완료는 아니다.** 사용자가 설정 미준비 상태임을 확인했고 [준비 절차](EOS_SETUP.md)를 정리했다.

## 변경 파일과 처리

- `src/AIrtist.Core/MultiplayerProtocol.cs`: 통신/규칙 버전과 모델 manifest·단어 목록 지문, 제출 요청·생성 승인·전송 정보, 최대 1,024바이트의 이미지 패킷 인코딩과 재조립. EOS 타입·새 패키지 의존성은 없다.
- `src/AIrtist.Core/MultiplayerRoundHost.cs`: 고정 참가자와 호환성 검사, 개인별 최종 묘사 승인·생성/전송 마감·그림 수집·기존 `VotingRoundHost` 진입. 경기 전체의 여러 라운드 스케줄러는 아직 없다.
- `tests/AIrtist.Checks/MultiplayerChecks.cs`, `Program.cs`: 모의 라운드·예외 검사와 기존 생성 PNG의 패킷 전송 검사 명령을 추가했다.
- `config/eos.example.json`, `scripts/check-eos-setup.ps1`, `.gitignore`: 빈 설정 예제, 로컬 준비 상태 확인, SDK/실제 설정 제외. 현재 앱 실행·배포에는 EOS 의존성이 없다.

`authenticatedPlayerId`는 향후 EOS가 식별한 실제 원격 사용자 ID를 전달할 경계다. 이번 검사에서는 모의 연결이 전달한다. 요청 본문의 PlayerId만으로 인증을 구현한 것으로 설명하지 않는다. 로비에서 확정한 참가자 목록·호환성을 생성자에 전달해야 한다.

최종 묘사의 원문과 영어 번역을 모두 금지 별칭 검사한다. 잘못된 입력은 생성권을 소비하지 않는다. 같은 승인 요청은 같은 승인 ID로 응답하고 내용 변경·두 번째 요청은 거절한다. 번역 준비/수정은 승인 API를 호출하지 않는다. 승인에는 제시어를 포함하지 않는다. 실제 클라이언트 연결 시 **중복 승인 응답으로 생성기를 다시 실행하지 않는 처리**도 필요하다.

이미지 전송 시작은 경기·라운드·제출 버전·송신자·승인 ID·전송 ID를 검사한다. 패킷의 전송 ID는 승인된 정보에 묶인다. 다른 참가자, 잘못된 길이·인덱스·분할 개수·프로토콜 버전은 거절한다. 순서 변경을 처리하고 같은 분할은 한 번만 반영한다. 내용이 다른 중복 분할, 전체 SHA-256 불일치, 잘못된 PNG는 실패 처리한다. 기존 `VotingArtwork`의 해상도·실제 디코딩 검사도 재사용한다.

완료된 그림은 교체할 수 없다. 전송 실패·시간 초과에도 새 생성권을 주지 않는다. 해시·디코딩 중 마감이 지나도 그림을 반영하지 않는다. 새 라운드 인스턴스는 이전 전송의 패킷을 받지 않는다.

## 임시 정책과 상한

| 항목 | 이번 구현 |
|---|---|
| 처리 인원 | 2~16명. 최종 제품 최대 인원·EOS 실측 아님 |
| 작성 | 시작 후 120초 기본값. 번역 확인·수정 포함 |
| 생성·업로드 | 개인의 제출 승인 후 180초 기본값 |
| 전송 | 전송 시작 후 30초 기본값. 생성 시간에도 포함, 재전송으로 초기화하지 않음 |
| 시간 변경 | `MultiplayerRoundPolicy`에서 설정. 단조 증가 시계로 판정 |
| PNG | 그림당 최대 4MiB, 가로·세로 최대 1024픽셀 |
| 패킷 | 32바이트 헤더 + 최대 992바이트 데이터. 분할 수도 상한 적용 |
| 전체 그림 | 미완료 예약과 완료 PNG 합계 최대 16MiB. 실패한 예약 해제 |
| 투표 | 기존 60초·전원 투표 종료·자기 투표 불가·선택 변경 불가 |
| 실패/미제출 | 기본 정책에서는 다른 유효 그림에 투표 가능 |
| 후보 부족 | 0~1개면 투표 없이 종료. 0표일 때 최다 득표자 없음 |

시간·실패 처리는 임시 기본값이다. 재시도·기권·이탈·동점·누적 우승 등 최종 규칙 확정은 아니다. 다음 라운드는 새 roundId와 별도 인스턴스를 사용한다. 명령/스냅샷 호출 때 마감을 진행하므로 실제 어댑터는 주기적으로 스냅샷을 갱신해야 한다.

16MiB는 **PNG 원본/수신 예약 상한**이며 디코딩 중 복사본·미리보기·SDK 큐까지 포함한 프로세스 메모리 상한은 아니다. `FromVerifiedAssets`의 지문 생성은 `RuntimeAssets.Verify`로 실제 자산을 먼저 검증한 뒤 수행한다. 지문 비교만으로 자산 무결성이나 악성 클라이언트 변조 방지가 보장되지는 않는다.

## 수행한 검사

.NET 10.0.103으로 수행했다. 외부 라이브러리·모델 버전은 변경하지 않았다.

- 전체 `unit` 통과: 기존 자산·단어·그림그리기·투표 검사와 새 멀티플레이 검사.
- 입력/번역·금지 별칭·빈 요청·다른 송신자·경기·라운드·버전 거절과 이후 정상 제출. 병렬 제출 20건 중 한 건만 승인.
- 모델·단어·규칙·통신 버전 불일치, 중복 참가자·인원 상한 거절.
- 미승인 전송, 소유자 위조, 다른 승인·라운드, 전송 ID 재사용, 파일/전체 메모리 상한 검사.
- 패킷 역순·중복, 잘못된 길이·인덱스·분할 수·버전, 충돌하는 중복, SHA 손상, 해시가 맞지만 PNG가 아닌 데이터 검사.
- 작성 마감 1ms 전 승인/정각 거절, 개인별 생성 시간 보장, 생성 마감 정각 거절, 패킷 누락·전송 시간 초과와 버퍼 해제. 재전송으로 제한 시간이 늘어나지 않음.
- 실패 알림 소유권·멱등성, 실패자의 투표 자격, 2인 1:1 동점, 해제 후 명령 거절.
- 기존 실제 Tiny-SD PNG 3장 **891,234바이트 / 900개 패킷**으로 모의 송수신. 원본 바이트·SHA-256 일치, 1/2/0표, 3명에게 직렬화한 결과 일치. 새 GPU 생성은 실행하지 않았다.
- WPF **Release 빌드 경고 0 / 오류 0**. 새 UI/SDK 연결과 `testbuild` 재패키징은 하지 않았다.
- 실제 설정·SDK·진단 결과의 Git 제외와 빈 예제 추적 가능 확인. 준비 검사 스크립트의 설정 미존재·빈 설정 분기 검사. 유효 SDK/자격 증명 확인은 미수행.

재현:

```powershell
$env:DOTNET_CLI_HOME = Join-Path (Get-Location) '.cache/dotnet'
$env:NUGET_PACKAGES = Join-Path (Get-Location) '.cache/nuget'
```
