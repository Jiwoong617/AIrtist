# 경기 실행기·로컬 AI·경기 미리보기 — 2026-09-27

이 문서는 한 라운드/v5 단계 기록이다. 2026-09-28 여러 라운드·결과 확인·기록 보존을 연결한 현재 v6는 [후속 보고서](MATCH_RUNTIME_REPORT.md)를 따른다.

**한 PC의 메모리 내 연결이다. EOS 인증·온라인 로비·인터넷 송수신을 구현하거나 검증한 결과가 아니다.** 기존 `testbuild`는 갱신하지 않았다.

## 실행 순서와 임시 규칙

실행기는 시작 메시지를 보낸 뒤 변경된 참가자 상태만 배포한다. 최종 제출을 호스트가 승인한 뒤 해당 참가자의 생성 입력을 한 번만 꺼낸다. 번역·생성에는 플레이어의 묘사와 기존 공통 스타일만 전달하며 제시어는 표시·입력 검사에 사용한다.

AI 취소·시간 초과·호스트 마감 이후에 돌아온 PNG는 제출하지 않는다. 생성 실패/취소는 승인 ID로 통지하며 이미 소비한 기회를 돌려주지 않는다. 아직 모델 작업이 종료되지 않았으면 같은 참가자의 새 작업을 받지 않는다. 번역 재작성은 작성 시간을 초기화하지 않는다.

갤러리 목록의 제어 ACK를 받은 참가자에게 이미지를 예약한다. 전원 이미지 수신 확인 후 투표 상태를 배포하고, 표가 바뀌거나 마감되면 해당 revision의 상태/결과를 배포한다. **그림이 0~1장인 조기 결과도 수신자가 준비된 뒤 보내도록 했다.** 그렇지 않으면 그림 수신 전 도착한 결과를 클라이언트가 거절한 뒤 다시 받지 못할 수 있었다.

전송 계층이 방장 연결 상실을 알리면 AI를 취소하고 새 요청을 멈추되 이미 확정된 결과는 보존한다. 참가자 이탈 시 기존 고정 명단과 마감 규칙을 유지한다. 전원 갤러리 확인에 실패하면 기본 60초 뒤 중단한다. 실제 EOS 이탈 감지·명단 재구성·재접속·호스트 이전은 없다.

미리보기 기본값은 **3명, 작성 300초, 생성 180초**이며 UI에서 2~4명과 1~600초를 선택한다. 긴 작성 기본값은 한 PC의 역할 전환 체험을 위한 값이다. Core 기본 작성 시간은 기존 120초를 유지한다. 생성 대기·업로드는 해당 참가자의 생성 제한에 포함된다. 투표 기본 60초·전원 투표 시 종료·선택 변경 불가·그림 없는 참가자 투표 허용·0~1장 무투표 종료도 기존 임시 정책이다.

`다시 설정`은 기존 라운드를 해제하고 새로운 ID의 한 라운드를 만든다. 여러 라운드 경기·누적 우승 규칙을 구현한 것이 아니다. 일반 실행은 결과 파일을 저장하지 않으며 진단 명령만 지정한 폴더에 기록한다.

## 검증 결과

### 모의 AI·패킷·시간 검사

.NET SDK **10.0.103**에서 전체 `unit` 통과. 기존 그림그리기·투표·갤러리·신뢰성 제어/이미지 전송·승인 검사도 통과했다. 새 실행기 검사는 다음을 포함한다.

- 3명의 번역 수정 → 승인 → 업로드 → 갤러리 → 투표/확정 결과를 자동 실행했다. 제어 데이터/ACK와 이미지 조각을 누락시켜도 복구하고 **1/2/0표**가 일치했다. 이 검사의 AI는 작은 PNG를 반환하는 대역이다.
- 제시어/영어 별칭·오래된 번역 확정·자기 표·중복 실행을 거절했다. 생성기 입력에 수정한 영어만 전달되는 것을 확인했다.
- AI 하나를 강제로 대기시킨 동안 다른 승인 작업들은 공유 실행기에서 기다렸다. 실제 대역 모델 진입은 한 번뿐이었고 대기 작업을 취소하면 모델에 진입하지 않았다.
- 생성 실패, 취소를 무시한 늦은 반환, 호스트 생성 마감 이후 반환을 검사했다. PNG를 제출하거나 생성권을 복구하지 않았다.
- 그림 0장/1장일 때 모든 참가자에게 무투표 결과가 도착했다. 방장을 해제해도 이미 확정한 결과가 남았다.
- 상태 위조/역행·재전송에 의한 시간 연장·로컬 전송 큐/패킷 크기 상한·바이트 복사 소유권을 검사했다.

### 실제 AI·WPF 실행

최신 Release 빌드는 **경고 0 / 오류 0**이다. `--round-smoke`가 실제 로컬 번역·Tiny-SD 생성, 수정된 묘사 제출, 이미지 업로드/배포와 투표를 통과했다. 역할 전환 시 원문/영어 수정 보존, 자기 투표 거절, 참가자별 확정 결과 일치도 확인했다. 별도로 `--self-check`로 그림그리기 진입 화면과 모델 검증을 통과했다.

검증 PC: **GeForce GTX 1660 Ti 6GB, 드라이버 591.86**, .NET **10.0.3 win-x64**, ONNX Runtime DirectML **1.22.0**, DirectML **1.15.4**. 기존 Tiny-SD 혼합 INT8 U-Net·TAESD 구성과 OPUS 번역을 재사용했다. **512×512, 25단계, guidance 7**, 기존 공통 2D 스타일이다. 새 모델·SDK·의존성을 추가하지 않았다.

|---|---|---:|---:|---:|---:|
| 빨갛고 둥근 과일 | a round red fruit | 42 | 1.54초 | 22.82초 | 392,226바이트 |
| 작은 초록색 과일 | a small green fruit | 43 | 1.32초 | 21.27초 | 573,723바이트 |

PNG 합계는 **1,294,269바이트**다. 생성 열은 승인·로딩·생성·로컬 전송까지 포함하므로 모델 단독 추론 시간이나 인터넷 전송 속도로 해석하지 않는다. 첫 모델 로딩만 따로 계측하지 않았다. 전체 진단 프로세스는 **76.91초**, UI 타이머는 **670회** 진행했다. UI 스레드에서 모델 추론을 실행하지 않았다.

약 0.5초 간격의 프로세스/장치 표본에서 최대 working set **1,693,032,448바이트**, private bytes **3,617,779,712바이트**였다. GPU 전체 사용량은 **990~4,151MiB**이며 다른 앱을 포함한다. 앱 전용 최대 VRAM이나 4GB GPU 지원을 검증한 값이 아니다. 런타임 DLL 네 개가 빌드 출력 폴더에서 로드됨을 확인했다.

번역은 이번 세 문장에서 `Red and round fruit`, `Small green fruit`, `Two red fruits.`를 반환했다. 정확도 개선 실험으로 해석하지 않는다. 실제 그림은 빨강/초록과 둥근 형태가 나타났지만 첫 그림에는 배경 장식이 추가됐고, 두 개를 요청한 세 번째 그림에는 과일이 세 개 나타났다. 기존 개수·세부 의미 보존 한계는 남아 있다.

1116×764 / 96dpi와 892×602 / 144dpi의 갤러리·결과 렌더를 확인했다. 작은 창에서는 스크롤로 나머지 그림/결과에 접근하는 구성이다. 실제 모니터 DPI 전환·한국어 IME 수동 조작은 이번 검사에 포함하지 않았다. Enter가 제출을 유발하지 않는 `AcceptsReturn`/기본 버튼 설정만 확인했다.

원시 결과는 Git 제외 경로 `outputs/multiplayer/round-runtime-20260927-r3/round-smoke.json`, `process.json`, `player-1.png`~`player-3.png`, `round-*.png`에 있다. 초기 실행에서 개발 출력의 단어 파일 누락을 수정했고, 두 번째 실행은 자기 투표 거절을 검사 코드가 잘못된 예외 종류로 받아 실패했다. 세 번째 실행이 위 최종 통과 결과다. 실패 시에도 프로세스 종료와 상태 JSON을 모두 확인하도록 진단을 보강했다.

## 재현·실행

모델은 이미 준비된 `models/app-stage3`를 사용했다. 모델 복제나 `testbuild` 재생성 없이 소스를 빌드해 실행한다.

```powershell
$env:DOTNET_CLI_HOME = Join-Path (Get-Location) '.cache/dotnet'
$env:NUGET_PACKAGES = Join-Path (Get-Location) '.cache/nuget'
dotnet run --project tests/AIrtist.Checks -c Release --no-restore -- unit .
dotnet build src/AIrtist.App -c Release --no-restore

# 일반 실행: 상단 '경기 미리보기'
& ./src/AIrtist.App/bin/Release/net10.0-windows/win-x64/AIrtist.exe --models D:/AIrtist/models/app-stage3

# 반드시 존재하지 않는 새 출력 폴더를 사용한다.
./scripts/check-app.ps1 -PackageDirectory src/AIrtist.App/bin/Release/net10.0-windows/win-x64 `
  -ModelDirectory models/app-stage3 -OutputDirectory outputs/multiplayer/round-runtime-next -Mode round-smoke
```
