# 그림 모아보기·투표·호스트 집계 — 2026-09-23

수정 기획의 **3번 로컬 구현·검증 단계**를 완료했다. 그림 목록, 자기 그림 구분, 한 사람당 한 표, 호스트 검증·집계와 고정 결과를 구현했다. `testbuild/AIrtist.exe` 상단의 **투표 미리보기**에서 실행할 수 있다. 실제 온라인 멀티플레이는 다음 단계다.

## 실행과 임시 규칙

한 PC에서 2~4명의 PNG를 선택하고 참가자 역할을 바꿔 투표한다. 최근 생성 그림은 플레이어 1에 가져오며, 두 장 이상 있어야 미리보기를 시작한다. 자기 그림은 표시하지만 버튼이 비활성화되고 직접 요청도 Core에서 거절한다. 참가자 이름은 공개하고 참가자 순서로 그림을 배치한다. 파일 가져오기와 역할 전환은 로컬 검사 수단이며 실제 게임의 제출·인증 방식이 아니다.

| 항목 | 이번 임시값 |
|---|---|
| 투표 시간 | 60초. `VotingPolicy.Duration`으로 변경 가능 |
| 조기 마감 | 전원 투표 시 종료, 방장도 마감 가능 |
| 선택 변경 | 확정한 한 표를 변경하거나 취소하지 않음 |
| 그림 없는 참가자 | 다른 사람 그림이 있으면 투표 가능. 정책 옵션으로 제한 가능 |
| 그림 0~1개 | Core는 투표 없이 종료. 미리보기 시작 버튼은 2장부터 활성화 |
| 미투표 | 표를 추가하지 않고 미투표 인원만 기록. 별도 감점 없음 |
| 동점 | 공동 최다 득표로 표시. 0표만 있으면 최다 득표자 없음 |
| 2인 | 서로 투표하면 1:1 동점 그대로 표시. 3인 이상을 강제하지 않음 |
| 재투표·누적 우승·이탈/재접속 | 미구현·정책 미확정 |

최종 제품의 인원·해상도는 확정하지 않았다. 현재 Core의 자원 상한은 16명, PNG당 4MiB, 가로·세로 각 1024픽셀, 라운드의 원본 PNG 총 16MiB다. PNG 헤더의 크기를 디코딩 전에 검사하고 실제 픽셀 디코딩까지 성공한 그림만 보관한다. 원본 바이트를 복사하고 미리보기 비트맵을 고정해 외부 수정으로 이미 승인한 그림이 바뀌지 않게 한다.

## 변경 파일과 책임

- `src/AIrtist.Core/VotingRound.cs`: 참가자·그림·정책·투표 요청/응답·집계 결과와 호스트 구현. 경기/라운드/투표 단계 버전, 인증된 호출자와 투표자 일치, 소유자, 대상, 마감, 한 표를 검증한다. 확정 표와 결과는 UI에서 계산하지 않는다.
- `src/AIrtist.App/VotingWindow.xaml`, `.xaml.cs`: PNG 선택, 그림 모아보기, 자기 그림·확정 선택 표시, 참가자 역할 전환, 마감과 결과 화면.
- `MainWindow.xaml`, `.xaml.cs`: 투표 미리보기 진입과 최근 그림 전달. AI 작업 중에는 진입을 막는다.
- `App.xaml.cs`, `scripts/check-app.ps1`: 실제 PNG 3장을 받는 `--voting-smoke` 진단.
- `tests/AIrtist.Checks/VotingChecks.cs`, `Program.cs`: Core 투표 회귀 검사. 기존 그림그리기·단어·자산 검사도 유지했다.
- `scripts/package-app.ps1`, 개발 지침·통합 기획서·README·개발 문서: 패키지 사용법·구현 상태·임시 규칙 갱신.

투표 단계의 `VotingVersion`은 같은 투표 단계에서 고정하고, 승인된 표와 결과 변화는 별도 `Revision`으로 증가시킨다. 다른 참가자의 표가 도착했다고 정상 대기 중인 참가자의 투표 요청이 낡은 버전이 되지 않는다. 같은 요청 ID·내용의 재전송은 중복 가산하지 않는다. 이미 승인한 요청은 마감 후에도 접수 사실을 다시 응답할 수 있지만 새로운 표나 다른 내용은 받지 않는다.

실제 마감 판정은 호스트의 단조 증가 시계로 하며 화면의 초 표시와 분리했다. 결과에는 경기·라운드·단계 버전·확정 revision·득표수·마감 사유·미투표 인원을 넣고 이후 호출에서 변경하지 않는다. 결과를 JSON으로 내보내 다시 읽을 수 있다.

## 수행한 검사

- 잠금 파일 기준 복원, Core·WPF Release 자체 포함 빌드와 패키징 통과. 기존 런타임·모델·의존성 버전은 유지했다.
- 모의 3인 표가 1/2/0으로 집계되고 모든 참가자의 확정 결과가 동일함을 확인했다. 결과 JSON 직렬화·복원, 확정 결과의 재마감 불변성 통과.
- 자기 표, 알 수 없는 참가자, 인증 호출자와 다른 투표자, 잘못된 그림, 다른 경기/라운드, 오래된 투표 단계 버전, 빈 요청 ID 거절.
- 동일 재전송, 같은 요청 ID의 대상 변경, 새 요청 ID로 두 번째 표, 같은 참가자의 병렬 요청 20개를 검사해 중복 가산이 없음을 확인했다.
- 마감 1ms 전 승인·정각 거절, 전원 투표 종료, 방장 마감·비방장 거절, 마감 후 신규 표 거절 통과.
- 2인 1:1 동점, 0표/그림 부족, 그림 없는 참가자의 투표 정책, 참가자·소유자·그림 중복 거절 통과.
- PNG 크기·헤더·해상도·불완전 데이터 거절, 바이트 복사본 수정으로 원본이 바뀌지 않음과 비트맵 고정 검사 통과.
- 기존에 Tiny-SD로 생성한 서로 다른 PNG 3장으로 실제 WPF EXE의 모의 투표를 검사했다. 자기 그림 비활성화와 Core 거절, 투표 후 버튼 비활성화, 역할 전환, 1/2/0표, 결과 일치, 새 미리보기 초기화 통과.
- 갤러리·결과의 100% 및 작은 화면 150% 렌더를 확인했다. 작은 화면은 스크롤로 그림을 비교한다. 실제 모니터 배율 전환·사람의 입력 검증을 대신하지 않는다.
- 최종 `testbuild`에서 그림그리기 자체 검사와 전체 패키지 파일 크기·해시 검사를 수행했다. 이번에는 생성 모델을 바꾸지 않았으며 GPU 이미지 생성을 다시 실행하지 않았다. 기존 생성 결과를 불러와 투표 화면을 검사했다.

진단 자료는 `outputs/voting/final-ui-check/voting-smoke.json`, 화면 PNG들, `outputs/voting/final-path-check/`, `final-package-size.json`에 있다. 이 파일들은 로컬 결과로 Git에서 제외한다.

## 배포와 다음 단계

현재 `testbuild`는 **922,301,469바이트 / 439개 파일**, 1GB 목표 대비 **77,698,531바이트** 여유다. 이전 패키지 대비 증가량은 **48,056바이트**이며 모델 파일과 의존성 추가는 없다. 폴더 전체를 함께 사용한다.

검증 후 이전 패키지·첫 후보 패키지·이번 빌드 중복 **2,318,462,406바이트**를 정리했다. 정리 직후 전체 작업 폴더는 **3,294,543,701바이트(약 3.29GB)**이며 모델과 실험 결과는 유지했다. [정리 기록](WORKSPACE_CLEANUP.md)

다음 단계는 **EOS 로비·P2P, 호스트 제출 승인·라운드 진행, 실제 그림 전송과 투표·결과 동기화**다. `VotingRoundHost` 생성자는 호스트가 승인한 참가자·완성 그림만 받는 경계다. 현재 파일 선택은 그 경계를 로컬에서 대체한다. 온라인 연결부는 인증된 연결의 플레이어 ID를 별도 인자로 전달해야 하며 클라이언트가 보낸 `VoterId`를 신뢰해서는 안 된다. 실제 패킷·서로 다른 회선·호스트 이탈·재접속·여러 라운드와 최종 우승은 아직 검증하거나 구현하지 않았다.
