# 메인 화면 디자인·같은 PC 멀티플레이

작성: 2026-10-14. 10월 13~14일 구현과 검사 기록이다.

## 사용 방법

1. `testbuild/AIrtist.exe`를 같은 Windows 사용자에서 두 개 이상 실행한다.
2. 첫 앱에서 **멀티 플레이 → 방 생성 → 방 만들기**를 누른다.
3. 다른 앱에서는 **멀티 플레이 → 방 참가**에 같은 방 코드를 입력한다.
4. 각 창에서 **게임 준비**를 누르고, 게임 대기방에서 준비한 뒤 방장이 시작한다.

사용자 요청대로 온라인/로컬 선택이나 테스트 전용 메뉴를 추가하지 않았다. 같은 PC의 방 코드를 자동 인식하고 앱마다 별도 참가자 ID를 부여한다. 인터넷·EOS 인증은 동일 PC 참가의 필수 조건이 아니다.

외부 PC 참가자는 기존 EOS 경로를 사용한다. 첫 참가자가 같은 PC이면 로컬 방으로, 외부 PC이면 EOS 방으로 고정한다. **로컬 참가자와 외부 PC 참가자를 한 방에 섞는 것은 지원하지 않는다.** 다른 방식으로 바꾸려면 새 방을 만든다. 다른 Windows 사용자·다른 PC의 LAN 연결도 이 로컬 기능의 범위에 포함하지 않는다.

## 메인 화면

- 연한 보라·녹색 배경, 그림 카드 장식, 붓 아이콘과 메뉴 카드로 구성했다.
- 그림 그리기·멀티 플레이·설정·종료 기능을 유지한다. 홍보성 문구나 부제를 넣지 않았다.
- WPF 벡터 도형으로 그려 별도 이미지 다운로드나 큰 이미지 에셋이 없다.
- 설정 화면에도 같은 색상·카드 스타일을 적용하고 해상도·음량 저장 동작을 유지했다.

## 연결 구조

- `AutomaticRoomConnection`은 생성 시 루프백 방을 준비하고 같은 코드의 EOS 방을 등록한다. 등록 실패가 로컬 연결을 막지 않는다.
- `LocalRoomAddress`는 사용자 임시 폴더 `AIrtist/local-rooms-v1`에 코드·루프백 포트·프로세스 ID/시작 시각·랜덤 접속 토큰·호환성 해시를 기록한다. 파일 크기를 제한하고 프로세스 생존/시작 시각을 확인한다. 정상 종료 시 자기 등록만 제거하며 비정상 종료의 오래된 등록은 사용하지 않는다.
- 같은 PC의 등록이 있으면 `127.0.0.1`에만 접속한다. 없으면 EOS 코드 검색으로 진행한다. 임의 외부 IP나 입력한 주소로 접속하는 기능은 없다.
- `LocalRoomConnection`은 정원·코드·토큰·호환성을 확인하고 소켓마다 독립 ID/세션을 배정한다. 방장이 명단을 고정하고 전원 준비·명단 수신 확인 후 공통 연결 ID와 `IRoundTransport`를 기존 Core에 전달한다.
- 방장이 TCP 패킷을 중계하면서 송신 소켓에 고정된 ID를 부여한다. 클라이언트가 보낸 송신자 ID는 허용하지 않는다. 경기·라운드·투표 권한 검사는 기존 Core에서 계속 수행한다.
- 연결 준비 이후 입퇴장/접속 상실은 해당 경기 연결을 중단한다. 확정 결과는 유지한다. 준비 이전의 입퇴장은 명단에 반영한다.
- 로컬 참가자가 먼저 연결되면 EOS 등록을 정리하고, EOS 참가자가 먼저 들어오면 로컬 등록/리스너를 닫는다. 아직 참가자가 없는 EOS 방에서 나갈 때는 서비스 응답을 기다린다.

## 자원과 제한

- TCP 프레임 상한 8KiB, 연결별 송수신 큐 각각 256개, 게임 패킷 1,024바이트, 게임 수신 큐 256개다. 한 번의 Tick에서 처리량도 제한한다.
- 가입 전 연결은 최대 20개, 가입 응답은 5초, 통신 무응답은 15초, 전원 준비는 60초로 제한한다. 현재 로컬 인원 상한은 기존 UI와 같은 16명이나 실측 경기는 3명이다.
- 모든 앱의 실제 이미지 생성은 `Local\AIrtist.Generation.v1` Mutex로 순차 실행한다. 모델 세션은 기존처럼 작업 종료 시 해제한다. 번역은 각 프로세스에서 수행한다.
- GPU 차례를 기다리는 시간도 기존 생성 제한 시간에 포함되며 취소할 수 있다. 여러 창 테스트에서 제한 시간이 짧으면 대기 중 시간 초과가 발생할 수 있다.
- 로컬 프로세스 간 연결은 EOS 사용자 인증과 구분한다. 동일 사용자의 테스트용 연결이며 변조 방지 보장을 하지 않는다.

로컬 경기의 오프라인 검사는 EOS 연결부가 실패하도록 한 대역을 사용했으며 통신 자체는 실제 TCP와 별도 EXE였다. 실제 물리 네트워크 차단·깨끗한 PC·낮은 사양·다른 Windows 계정 검사를 의미하지 않는다. 여러 PC의 실제 EOS P2P·PNG·투표는 계속 미검증이다.

## 빌드와 재현

실행 파일은 `D:\AIrtist\testbuild\AIrtist.exe`다. 전체 패키지는 **943,543,075바이트 / 444개 파일**, 1GB 목표 내다. 이전 빌드는 `.cache/testbuild-before-local-20261014`에 보존했다. EXE만 옮기지 말고 폴더 전체를 사용한다.

```powershell
# 실제 TCP, EOS 실패 대역, 모의 AI, 독립 앱 3개
.\scripts\check-local.ps1 -PackageDirectory testbuild -OutputDirectory outputs/local-new
# 실제 Tiny-SD를 각 프로세스에서 실행
.\scripts\check-local.ps1 -PackageDirectory testbuild -OutputDirectory outputs/local-real-new -RealAi
# 실제 EOS 등록 후 로컬 전환과 등록이 없는 코드의 EOS 조회
.\scripts\check-local.ps1 -PackageDirectory testbuild -OutputDirectory outputs/local-online-new -OnlineHost
```

출력 폴더는 매번 새 경로를 사용한다. `-OnlineHost` 검사에는 인터넷 연결이 필요하다.
