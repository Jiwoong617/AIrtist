# 생성 전 번역 확인·수정 — 2026-09-20

> **과거 구현 기록:** 2026-09-21부터 AI 채점과 싱글 경기를 폐지했다. 아래는 당시 EXE의 검증 기록이며 현재 `testbuild`는 [그림그리기 버전](DRAWING_MODE_REPORT.md)이다. 번역 확인·수정은 재사용하지만 제시어·작성 마감·생성권·점수는 적용하지 않는다. 이후 작업은 [통합 기획서](../AI_Image_Game_Summary.md)를 따른다.

**자동 번역을 확인하고 수정한 뒤 한 장을 생성하는 오프라인 흐름을 구현했다.** 사용자가 선택한 개선 방향이며 번역 모델의 정확도 자체를 높인 작업은 아니다. 최신 실행 파일은 `testbuild/AIrtist.exe`, 폴더 전체는 **963,323,328바이트 / 443개 파일**이다. 1GB 예산에서 36,676,672바이트가 남는다. 이전 패키지보다 13,105바이트 늘었으며 모델·런타임 다운로드는 추가하지 않았다.

## 동작과 임시 규칙

1. 제시어를 직접 쓰지 않고 원문을 2~160자로 작성한 뒤 **번역 확인**을 누른다.
2. 실제 로컬 번역 결과를 오른쪽에서 확인한다. 원문은 읽기 전용으로 남아 비교·복사할 수 있다.
3. 영어 묘사를 2~320자 범위에서 수정하거나 **원문 다시 쓰기**로 돌아간다. 영어로 작성한 원문도 같은 확인 화면을 거친다.
4. **확정하고 한 장 그리기**를 누르면 Core가 최종 묘사를 검사하고 생성 기회를 한 번 소비한다. 수정 문장은 다시 번역하지 않고 생성기에 전달한다. 입력 앞뒤 공백 제거와 NFKC 정규화는 적용한다.

번역 준비·확인·수정은 작성 제한 시간에 포함하는 임시 규칙이다. 기본 작성·확인 합계는 60초이며 시작 화면에서 30/60/120초로 바꿀 수 있다. 재작성·번역 실패·번역 취소로 시간이 초기화되지 않는다. 확정 전 번역 실패·취소는 생성 기회를 소모하지 않고 작성으로 돌아간다. 작성 마감·건너뛰기는 0점으로 끝난다. 확정 후 생성·채점은 별도 AI 제한 시간(기본 180초)을 사용하며 실패·취소·시간 초과는 기존대로 0점이다.

원문과 최종 영어 묘사 모두 금지 별칭·특수 토큰·길이를 검사한다. 번역이 제시어를 포함한 경우에도 확인 화면에서 수정할 수 있으며, 해당 단어를 남긴 채 확정하면 거절한다. 전각 영문이나 띄어쓰기 삽입도 기존 별칭 정규화 규칙을 적용한다. 한글이 남은 확인란은 영어로 고치거나 원문 재작성을 안내한다. 거절된 확정은 생성 기회를 소모하지 않는다.

제시어·별칭은 번역·생성 함수에 전달하지 않는다. 다만 **사용자가 수정한 문장이 원문과 같은 뜻인지 자동으로 증명하지는 않는다.** 영어를 읽고 수정해야 하는 부담과 자동 번역의 오역은 남는다. 자동 번역·채점 품질 전체를 통과로 판정하지 않는다.

## 구현 위치

| 파일 | 변경 |
|---|---|
| `src/AIrtist.Core/MatchController.cs` | 번역 준비·확인 상태, 초안 ID, 작성 마감 공유, 재작성·취소·확정 권한 |
| `src/AIrtist.Core/InputRules.cs` | 수정 영어의 길이·한글·별칭·특수 토큰 검사 |
| `src/AIrtist.Core/RoundController.cs` | 검증된 최종 묘사를 재번역 없이 생성하고 기존 1회 승인·실패 처리 유지 |
| `src/AIrtist.App/MainWindow.xaml`, `.xaml.cs` | 확인·수정 화면, 원문 복귀, 남은 시간, 작은 창 스크롤, 진단 흐름 |
| `tests/AIrtist.Checks/TranslationReviewChecks.cs`, `MatchChecks.cs`, `Program.cs` | 수정 문장 전달·마감·중복·오래된 초안·늦은 결과·취소·종료 검사 |
| `scripts/package-app.ps1` | 배포 README의 새 조작법 |

번역과 생성은 동시에 실행하지 않는다. UI 버튼 상태와 별도로 Core가 현재 경기 버전·초안 ID·상태·작업 정리를 검사한다. 이전 초안으로 확정하거나, 번역 취소/마감 뒤 늦게 반환된 결과를 사용하거나, 같은 초안을 두 번 생성할 수 없다. 생성 승인 뒤에는 확정 문장이 고정된다.

## 검증

- C# 규칙·경기 검사와 새 번역 확인 검사 통과. 확인 전 생성 거절, 원문·수정 문장의 금지어, 잘못된 수정 후 권리 보존, 재작성 시 마감 유지, 정확한 수정 문장 전달, 재번역 없음, 오래된 초안·중복 확정 거절을 확인했다.
- 수동 시계로 작성 마감 경계를 검사했다. 번역 오류, 취소, 토큰을 무시한 번역기의 늦은 완료, 마감 뒤 정리, 확인 중 건너뛰기, 번역 중 종료도 확인했다.
- 실제 WPF 패키지에서 한국어 번역 확인 → 영어 금지어 수정 거절 → 원문 복귀 → 재번역 → 올바른 영어 수정 → 실제 생성, 다음 라운드 건너뛰기, 영어 입력 확인·실제 생성, 3라운드 최종 결과와 새 경기 초기화까지 통과했다.
- 실제 생성에 사용된 수정 문장은 `a small animal with long ears and white fur`이며 완료 결과의 문장도 동일했다. 이는 생성 이미지 품질이나 평가점의 정확도 합격을 뜻하지 않는다.
- 최종 경기 검사 **48.89초**, UI 타이머 **421회**. GTX 1660 Ti 6GB/드라이버 591.86, Ryzen 5600X/RAM 약 48GiB. 프로세스 최대 working set 약 1.69GB, private bytes 약 3.62GB. .NET·ORT·DirectML이 패키지에서 로드됐다. 별도 저사양 PC 측정은 아니다.
- 확인 화면의 100%·150% 렌더와 최소 창에 해당하는 콘텐츠 영역을 검사했다. 작은 창에서 잘리던 입력 영역은 스크롤로 접근 가능하게 수정했다. 두 입력란의 Enter는 줄바꿈이고 확정 버튼의 기본 Enter 동작은 꺼져 있다. 실제 사람의 한국어 IME 조합, 모니터 이동/DPI 전환 검사를 대신하지 않는다.
- 새 패키지 442개 등록 파일의 크기·SHA-256을 확인하고 `testbuild`로 교체한 뒤 최종 경로의 자체 검사도 통과했다. manifest 자체를 합하면 443개 파일이다.

원자료: `outputs/translation-review/unit-checks.txt`, `packaged-match-final/`, `package-size-final.json`, `final-path-check/`. 이전 `packaged-match`는 작은 창 배치 수정 전 검사다. 최종 기록의 `testbuild-review-fixed`는 `testbuild`로 이동하기 전 경로다. 모델·실험 결과·패키지·bin/obj는 Git에서 제외한다. 이전 패키지와 이번 중복 빌드 산출물 **2,400,472,182바이트**를 정리했고 전체 작업 폴더는 약 3.80GB다. 정리 후 현재 패키지 등록 파일의 크기·해시도 일치했다. [폴더 정리 기록](WORKSPACE_CLEANUP.md)에 세부 수치를 남겼다.

재현은 기존 [앱 빌드·검사 명령](APP_DEVELOPMENT.md)을 사용한다. `unit`에 새 상태 검사가 포함됐고, 패키지의 `--match-smoke`에 실제 확인·수정·재작성 경로가 포함됐다.
