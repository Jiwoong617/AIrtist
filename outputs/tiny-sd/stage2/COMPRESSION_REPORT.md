## 결론

U-Net 혼합 INT8와 TAESD 디코더를 조합해 추론 모델 구성을 **1,062,108,664 → 579,084,853바이트**로 줄였다. 원본·TAESD·INT8·조합 각각 48개의 같은 입력 표본, 총 192장의 비교 자료를 만들었다. 추가 학습은 수행하지 않았다.

ONNX 생성 모델·토크나이저·스케줄러와 선정한 네이티브 DLL 합은 **618,923,747바이트**다. 최종 실행 옵션에서 DirectML로 512×512·25단계 생성 3건이 통과했으며 같은 입력의 PyTorch 결과와 색상 채널당 최대 차이는 1/255였다. 기본 DirectML 옵션과 graph fusion만 끈 설정은 실패 기록이 있으므로 이 설정을 생략해도 동작한다고 보장하지 않는다.

경량화 후에도 한국어 직접 입력과 일부 형태·관계·개수 묘사의 품질 한계가 남았다. 다음 단계는 **C# 최소 앱에서 검증한 실행 설정의 적용 가능성 확인, 로컬 번역·채점 연결, 전체 배포 용량 실측**이다. 게임 앱은 아직 구현 전이다. 작업 폴더의 개발 환경·중간 모델이 큰 이유는 [용량 설명](WORKSPACE_SIZE.md)에 따로 정리했다.

## 적용 구성

추가 학습 없이 Tiny-SD U-Net의 147개 Conv2d/Linear 가중치를 출력 채널별 INT8로 저장했다. 입력·출력층, 시간 임베딩, 정규화·편향은 부동소수점으로 유지했다. 텍스트 인코더는 양자화하지 않았다. 실행 활성값은 모든 구성에서 FP32다. INT8 활성값 연산이나 가속 효과를 검증한 것은 아니다.

복원기는 공개 TAESD의 디코더만 추출해 별도로 비교한다. 원래 VAE와 다르게 latent scaling factor는 1.0을 적용했다. 전체 TAESD와 디코더만 로딩한 결과가 동일한지 확인했으며, 양자화 체크포인트도 저장·재로딩 후 모든 state key와 값이 일치하는지 확인했다. [변환 기록](variant-manifests.json)

원본 Tiny-SD 리비전은 `cad0bd7495fa6c4bcca01b19a723dc91627fe84f`, TAESD는 `614f76814bbe30edbe2e627ace1c2234c81a2c0e`로 고정했다. Optimum Quanto 0.2.7, ONNX 1.19.0, ONNX Runtime DirectML 1.22.0을 사용했다. 기존 PyTorch 2.8.0+cu126, Diffusers 0.35.1, Transformers 4.56.2 환경을 유지했다. [전체 패키지 잠금 파일](../../../experiments/tiny_sd/requirements-stage2-lock.txt)

실측 PC는 Windows 11 빌드 26200, Ryzen 5 5600X, GTX 1660 Ti 6GB(드라이버 591.86), OS 가용 총 물리 메모리 약 47.93GiB이며 Python 3.12.14를 사용했다. 4GB VRAM·16GB RAM 기기의 측정값은 아니다.

## ONNX 변환 검증

opset 17, CFG batch 2, latent 64×64, token 77의 고정 크기로 내보냈다. 저장된 Quanto INT8 값·scale과 ONNX의 147개 가중치가 모두 대응하는지 검사했다. DequantizeLinear 뒤의 연산은 FP32이며, 실행기 내부에서 FP32 가중치로 펼쳐질 수 있다. 파일 크기 감소가 같은 비율의 실행 메모리 감소를 보장하지 않는다.

CPU에서 같은 입력과 같은 가중치의 PyTorch 출력에 대한 차이를 측정했다.

| 부품 | 최대 절대 오차 | RMSE |
|---|---:|---:|
| 텍스트 인코더 | 0.00001144 | 0.0000006514 |
| TAESD 디코더 | 0.00001299 | 0.0000007975 |
| INT8 U-Net | 0.00000763 | 0.0000008160 |

U-Net의 원본 가중치 대비 RMSE는 0.0040272다. 의도한 양자화 변화와 변환기/실행기의 수치 차이를 구분했다. 0.01 최대 절대 오차 상한은 이 실험의 변환 오류 감지 기준이며 의미 품질 합격선이 아니다. [CPU 검증 원자료](onnx-cpu-01/results.json)

### DirectML 실패와 최종 통과 설정

1. 기본 graph fusion에서 U-Net 실행은 `887A0006` GPU 오류로 실패했다. 한국어 오류 메시지를 UTF-8로 읽지 못한 예외도 함께 발생했다. [실패 기록](onnx-dml-01/results.json)
2. `ep.dml.disable_graph_fusion=1`로 세 부품의 고정 입력·3회 호출 수치 검사는 통과했다. 그러나 전체 생성 반복에서는 같은 GPU 오류가 재발했다. 부품 검사만으로 연속 생성 성공을 판단할 수 없었다. [부품 검사](onnx-dml-unfused-02/results.json) · [전체 경로 실패](../runs/stage2-onnx-pipeline-01/summary.json)
3. graph fusion 비활성에 더해 DirectML provider option `disable_metacommands=True`를 적용했다. 이 설정에서 고정 입력 검사와 전체 생성 3건이 통과했다. OS·드라이버·TDR 설정은 변경하지 않았다. 두 옵션은 [ORT 1.22.0 세션 키](https://github.com/microsoft/onnxruntime/blob/v1.22.0/onnxruntime/core/providers/dml/dml_session_options_config_keys.h)와 [provider option 구현](https://github.com/microsoft/onnxruntime/blob/v1.22.0/onnxruntime/core/providers/dml/dml_provider_factory.cc)에 근거한다.

GPU 전체 값에는 다른 앱이 포함되며 전용 프로세스 VRAM 수치가 아니다. [전체 생성 원자료](stage2-measurements.json) · [이미지·해시·픽셀 검증](onnx-pipeline-comparison.json)

실험 중 데스크톱 부하도 변했으므로 최적화 옵션 하나만이 오류의 원인이라고 확정하지 않는다. 이 PC·드라이버·모델·옵션에서의 3건 통과이며 모든 GPU나 장시간 실행에 대한 안정성 보장이 아니다. C# 연결에서 동일 옵션 적용과 반복 실행을 다시 확인해야 한다.

## 비교 조건과 실행 비용

원본과 동일한 12개 간접 묘사 × 2언어 × 2시드, 512×512, 25단계, CFG 7을 사용한다. 생성기에 정답 이름은 전달하지 않는다. 첫 생성 1회와 동일 입력 반복 2회를 품질 표본과 구분한다.

현재 GPU 부하가 원본 측정 때와 다르며, 사용자의 요청에 따라 다른 앱을 닫지 않고 진행했다. 일부 CPU 변환·검사도 품질 생성과 겹쳤다. 따라서 이번 소요 시간과 원본 평균 7.94초로 가속률을 계산하지 않는다.

TAESD 초기 실행은 36장(품질 33장)을 저장한 뒤 한 장 생성이 수분씩 지연되어 실험 프로세스만 중단했다. OS의 메모리 페이징 원인을 계측한 것은 아니다. 기존 이미지·소스·설정을 보존하고 해시를 검사한 뒤 새 실행 폴더로 이어받았다. 이후에는 신경망 부품을 순서대로 GPU에 올리는 model CPU offload를 사용해 남은 15장을 완성했다. 원본·TAESD 체크포인트와 생성 설정은 바꾸지 않았다.

| 확인한 실행 구간 | 횟수 | 첫 호출 | 구간 평균 | 가장 느린 완료 호출 | PyTorch 할당 피크 |
|---|---:|---:|---:|---:|---:|
| TAESD 초기, 전체 GPU 상주 | 36 | 17.09초 | 23.76초 | 237.54초 | 2,190,017,536바이트 |
| TAESD 재개, 부품별 offload | 15 | 12.77초 | 20.04초 | 33.95초 | 1,690,336,256바이트 |
| INT8 전체, 부품별 offload | 51 | 11.07초 | 20.79초 | 37.08초 | 1,150,465,024바이트 |
| INT8+TAESD 전체 경로 smoke, offload | 3 | 41.01초 | 32.79초 | 41.01초 | 837,213,184바이트 |

행마다 데스크톱 부하와 입력 구성이 다르다. TAESD 두 구간을 합친 평균으로 offload 성능을 판단하지 않는다. 마지막 행은 최초 영어·한국어·같은 영어 입력의 3회이며 다양한 묘사의 성능 대표값이 아니다. CPU offload의 최초 모델 로딩은 CPU 준비까지이며 GPU 전송 비용은 첫 생성에 포함된다. [TAESD 구간별 원자료](taesd-segment-measurements.json) · [전체 실행·환경](stage2-measurements.json)

INT8의 CPU 모델 준비는 1.94초, 첫 생성 이후 50회의 평균은 20.98초, 중앙값은 19.09초였다. 프로세스 RSS 샘플 피크는 3,632,369,664바이트, PyTorch reserved 피크는 1,843,396,608바이트다. TAESD 재개 구간의 RSS 샘플 피크는 3,753,553,920바이트다. 변형 모델의 무결성·재로딩 검사도 준비 시간에 포함하며 콜드 디스크/최초 설치 로딩 실험은 아니다.

조합 품질 48장의 **TAESD 복원만** 평균 0.163초, 최초 0.345초였고 GPU 할당 피크는 206,766,592바이트였다. U-Net과 텍스트 인코더를 실행하지 않은 이 값으로 전체 생성 속도나 메모리를 설명하지 않는다.

TAESD 48개 품질 표본의 무결성 검사가 통과했다. 영어에서는 원본의 주요 외형이 유지되면서 빨강·초록의 채도가 강해지고 작은 질감·경계가 바뀌는 사례를 관찰했다. 원본의 과일 형태·상하 관계·개수 실패가 해결된 것은 아니다. 품질 관찰은 이 묘사·시드 표본에 한정한다.

INT8 단독과 별도 조합 전체 경로에서 `fruit_red`의 한국어·영어, 시드 20260913의 마지막 latent 해시가 각각 일치했다. 조합 품질 48장은 INT8 단독 실행에서 저장한 동일 latent를 TAESD로 복원해 비교했다. 별도 전체 경로의 두 이미지와 캐시 복원 이미지도 픽셀이 정확히 일치했다. 이 방식은 디코더 외의 차이를 통제하며, 48쌍을 독립적으로 디노이징한 결정성 실험은 아니다. [독립 실행 2쌍 검사](independent-combined-latent-check.json)

## 품질 관찰과 판단

Codex가 영어·한국어 비교 시트 16개의 총 192개 출력을 관찰했다. 독립 평가자의 블라인드 평가나 게임 점수 산식 검증은 아니다.

| 묘사 범위 | 원본 대비 경량화 관찰 |
|---|---|
| 빨강·초록 과일, 흰 긴 귀 동물 | 주요 색과 형태는 대체로 유지했다. INT8에서 귀·몸 비율, 과일의 윤곽·질감이 바뀌는 사례가 있다. TAESD는 채도를 강하게 표현하는 경향이 보였다. |
| 휘어진 과일·비를 막는 덮개 | 원본의 감귤 단면·추상 형태 같은 실패가 남았다. INT8에서 덮개 윤곽이 더 크게 달라진 사례도 있어 무손실 품질이라고 부를 수 없다. |
| 빨간/파란 용기 | 주요 구성을 유지했지만 파란 용기의 시드 42에서 INT8가 바닥 받침과 윤곽을 바꿨다. 원본의 비정상 손잡이·색상 부족도 남았다. |
| 상자 위/아래 구체 | 서로 매우 비슷한 원판·공으로 표현돼 위치 관계를 충분히 반영하지 못하는 한계가 남았다. |
| 줄무늬 유무 | 패턴 유무 차이는 유지했다. TAESD와 INT8에서 가는 선의 모양·밀도·대비가 변했다. |
| 용기 두 개 | 시드에 따라 겹친 용기/분리된 두 용기가 나오는 차이가 남았다. 정확한 개수를 항상 보장하지 못했다. |
| 한국어 직접 입력 | 음식·접시·장식 무늬 등으로 벗어나는 경향이 세 변형에서도 남았다. 경량화로 언어 이해 문제가 해결되지 않았다. |

원본 대비 48장 평균 픽셀 RMSE(0~255)는 TAESD **10.66**, INT8 **7.38**, 조합 **13.21**이다. 이는 이미지 변화량이며 낮을수록 의미 정확도가 높다는 뜻이 아니다. [표본별 픽셀 차이](comparison-measurements.json)

현재 조합을 다음 앱 연결 단계의 **용량·실행 후보**로 사용한다. 추가 학습이나 4비트 양자화는 수행하지 않았다. 한국어는 의미를 보존하는 로컬 번역 후보를 비교해야 하며, 영어에서도 실패하는 제시어·묘사는 별도 검수와 평가가 필요하다.

## 완료한 검사와 남은 범위

- 체크포인트 저장·재로딩, TAESD 디코더 분리, 모델/이미지/잠재값/실행 소스 해시 검사 통과.
- 원본 포함 48×4 품질 매트릭스, 금지 별칭 미포함·토큰 잘림 없음·비정상 수치/단색 출력 없음 확인. 실험용 별칭 검사이며 제품 입력 검사기는 아직 아니다.
- ONNX CPU 및 최종 DirectML 설정의 부품별 수치 검사, 3개 묘사의 25단계 전체 생성·픽셀 비교 통과.
- Python 문법과 PowerShell 준비 스크립트 구문 검사, 의존성 검사 수행. 제품 앱 테스트는 앱 구현 전이므로 수행하지 않았다.
- C# API에서 같은 실행 옵션 적용, 번역·채점 모델, .NET 자체 포함 배포, 모든 라이선스/네이티브 의존성의 최종 집계, 4GB VRAM·16GB RAM 기기, 장시간 반복, EOS, 깨끗한 Windows 설치는 남아 있다.
